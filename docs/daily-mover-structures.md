# 合约结构观察第一版

本功能在原异动榜之外保存结构观察，不改变 `daily-mover-v2` 的入榜、盘口筛选和排名，不提供做多评分。所有条件使用完整 UTC 日 K。

展示中的「平台区间」与结构状态对应：上涨/回撤阶段解释尚未确认的具体原因；形成中展示符合整理条件的尾部窗口，标注「暂定整理范围 · 未确认」；已确认时显示冻结上下沿及确认日期；失效时保留原边界并标注失效日期。解释使用原记录的输入与参数生成，不修改历史判断。暂定范围不参与触发价、失效价或 R 的计算。

## 页面

当前页面重点为趋势向上 / 向下延续，平台结构作为可展开的背景依据。当前规则单独版本化为 `continuation-trial-v1`。

### 趋势延续边界

- 上侧优先使用此前已确认且尚未失效的平台上沿，下侧使用平台下沿。没有可用平台则分别使用最近 30 日中、本观察周期内最近已确认的日线高点和低点；拐点需要左右各 2 根完整日 K 确认。没有已确认拐点时使用周期内截至此前日 K 的最高 / 最低价，标注待验证。
- 两侧各自以参考价 ±0.25 ATR14 构成边界区域，单侧宽度限制为参考价的 0.5%～3%。ATR 是此前 14 根日 K 真实波幅的简单平均值，建立边界至少需要此前 15 根连续日 K，不使用当前判断 K 或未来价格。
- 向上延续需要收盘严格高于上侧区域上沿；向下延续需要收盘严格低于下侧区域下沿。首次越界标注待站稳，边界冻结；连续 2 根完整日 K 收盘留在外侧确认向上站稳 / 向下保持。日内刺穿和区间内横盘不算突破。
- 高位 / 低位横盘检查越界后最近 3 根日 K：全部影线范围也在边界外，影线总宽度 `(最高/最低-1)` ≤12%，收盘跨度 `(最高收盘/最低收盘-1)` ≤8%。横盘范围单独展示，和原突破边界区分。
- 后续 K 线触及边界区、但收盘仍在外侧，分别标注回踩守住 / 反抽未收复。收盘返回边界内则标注未守住，保留事件，下一根日 K 按此前已知依据重新建立边界。
- 高低点结构独立比较最近两组已确认日线拐点，展示高点抬高 / 降低与低点抬高 / 降低；不把单日涨跌冒充结构趋势。
- 新结构记录保存延续规则、边界和事件并纳入 JSON 校验摘要。旧记录仅按留存 K 线回算，榜单、移动端、详情和观察池均标注回算来源，不改写原发布记录。
- 延续边界不生成入场、止损或 R；旧版观察方案仅留作历史计算兼容，不作为当前主展示。

### 旧版多空注意力方案（历史口径）


- 当前走势描述最新日 K 相对前收盘的上涨/回落，以及是否超过此前 10 日高点；它与原平台结构状态分别展示。
- 优先使用当前时点此前已确认的平台下沿；没有平台则使用本轮高点后的回撤低点。局部低点按左侧 2 根、右侧 2 根确认；尚未确认的回撤低点明确标注待验证。没有回撤低点时选最新已确认日线低点，再缺少则用最近 10 日窗口低点并标注待验证。
- 参考位单侧宽度为此前 14 根日 K 真实波幅均值（简单 ATR14）的 0.25 倍，限制在参考价的 0.5%～3%。计算至少需要 15 根连续日 K，不使用当前确认 K 或未来 K 修改初始宽度。
- 多头：进入区域后等待连续两日最低价不下降，并在后续日 K 收盘超过已确认反弹高点 0.5% 及区域上沿。反弹高点用左侧 1 根/右侧 1 根确认，确认 K 必须已经完成。失效参考为区域下沿再减参考价 0.5%。
- 空头：先收盘跌破区域下沿，再等待后续某根日 K 反抽价格范围与区域相交、收盘回到下沿之下并收阴。触发后的失效参考为该反抽日高点与区域上沿的较大值，再加参考价 0.5%；未反抽确认时不伪造入场和失效价。跌破后收盘重新站上区域上沿，则跌破依据失效。
- 进入观察、跌破或入场条件成立后区间冻结。失效事件保留，只有失效后出现新的已确认低点才允许建立下一套方案。未进入/未跌破的候选区域可随此前已知的新依据更新。建立当根 K 不能直接成为入场信号。
- 入场区域在触发后以触发日收盘 ±0.1 ATR 计算，同时限制在有效失效/目标边界之内；是历史计划参考，不是保证能成交的价格。R 分方向计算，多头 `(压力-入场)/(入场-失效)`，空头 `(入场-支撑)/(失效-入场)`。目标使用触发前已确认的日线局部高/低点；未确认入场或无有效目标时不计算 R。
- 新的正式结构记录将注意力方案、规则和事件一起保存进不可变 JSON，纳入校验摘要。旧结构记录只在展示时按原留存日 K 回算，并标注「新规则回算」，不覆盖原记录或冒充当时已发布的入场判断。

所有范围及参数为第一版研究口径，尚未通过收益验证。日线观察不提供日内即时下单信号，也不增加做多/做空评分。

- `/daily-movers/`：原榜单展示当前走势、向上 / 向下延续边界、下一步确认条件和已确认高低点结构。
- `/daily-movers/structures/`：正式结构观察池；可按日期、合约筛选，默认显示正在跟踪的记录；可筛选只看已出榜的币，或只看已停止跟踪的历史记录（archive=1），后者不包含仍在跟踪的记录。停止状态按所选观察日期判断。
- `/daily-movers/structures/?origin=replay`：独立的历史回放观察池。
- `/daily-movers/<symbol>/?date=YYYY-MM-DD&origin=replay`：该日回放判断、上下延续边界和横盘范围、输入日 K、校验摘要和事件历史。

## 试用规则 structure-trial-v1.1

以下参数是第一版的可复核观察口径，未经收益验证。

1. 正式前 30 名首次出现时创建观察周期，固定首次入榜信号的区间低点和日期为启动锚点。它是区间低点基准，不声称准确识别了真实启动前价格。
2. 采集 90 日完整日 K 作为初始结构和压力背景；后续沿用已保存输入并追加新 K 线。新上市、缺口、异常 OHLC、缺少截止日或启动锚点时显示数据不足。不会使用截止日期之后的输入。
3. 平台形成前，高点随严格创新高更新。高点之后最近连续 5 日影线总宽度 `(最高/最低-1)` 不超过 12%，收盘跨度不超过 8%，则平台暂时成立。上下沿为该确认窗口的最高和最低价，确认后冻结。确认当天不判断该新平台突破。
4. 高点后至少 2 日连续满足上述宽度条件、但尚未形成平台时标记平台形成中；仅从高点回落而不满足条件时标记回撤中。
5. 下沿观察区域为 `[下沿, 下沿+平台宽度×20%]`，单根日 K 价格范围与之相交仅记录进入观察。
6. 回撤确认：进入观察后，连续两日最低价不下降；反弹局部高点必须高于左侧日高、且不低于右侧日高，右侧 K 完成后方可使用；后续收盘超过已确认高点 0.5% 时触发。参考入场为触发日收盘，失效价为观察后截至触发日最低价 ×0.995。触发后的这些价格冻结。
7. 平台突破：后续日 K 收盘超过冻结上沿 ×1.005 时触发。参考入场为触发日收盘，失效价为下沿 ×0.995。之后某日最低价落在上沿 ±0.5% 内且收盘高于上沿，单独记录回踩确认。日内刺穿不等于日线失效。
8. 收盘低于平台下沿 ×0.995 时记录平台失效，不因后续恢复撤销。回撤方案还可在触发后收盘低于自身失效价时独立失效。
9. 首个压力取入场参考价上方最近一个此前已确认的日线局部高点或本轮原高点；不使用当前触发 K 和未来 K 识别压力。压力不是成交目标承诺。无有效压力或入场/失效依据时 R 无法计算。
10. 未触发时为计划参考 R；触发时用触发日收盘重新计算并冻结。R 仅描述 `(压力-入场)/(入场-失效)`，未计成本，不代表预期收益或当前剩余空间。
11. 平台代表价为确认窗口收盘中位数。启动倍数为 `代表价/锚点`；成果保留率为 `(代表价-锚点)/(原高点-锚点)`。

## 跟踪周期和时间

掉榜后继续采集，达到 30 日时结束周期；再次入榜更新最后在榜日期。平台失效后完成 10 日后续观察，或掉榜期限到达，取先发生的结束条件。结束后记录保留，再次入榜创建新的观察周期；第一版不在活跃周期中自动推断新一轮上涨。

榜单日期对应扫描日期，价格截止为前一 UTC 日期的日 K；页面分别展示 K 线日期、数据区间结束时间、判断生成时间和盘口时间。缺少整个榜单日期时跳过该日入榜判断，不把缺少榜单当作该日确认掉榜；显示的掉榜天数是距最后已知在榜日期的日历天数。

正式快照和结构判断不可覆盖。独立结构记录保存版本、输入与判断 SHA-256、计算输入和事件。后续版本创建新记录，旧版本仍保留。历史回放不冒充当时发布的判断；试算样本可能受现时盘口和现存合约筛选影响，不用于无偏收益统计。

## 运行

WSL Ubuntu 项目根目录 `/home/jacky/market-evidence-lab`：

```bash
uv run python manage.py migrate
uv run python manage.py update_mover_structures --replay
# 单币历史回放
uv run python manage.py update_mover_structures --replay --symbol GTCUSDT
# 当日正式榜单完成后补采结构
uv run python manage.py update_mover_structures
```

已有的 `scan_daily_movers` 和统一调度器在正式榜单完成后更新观察池，包括掉榜合约。结构采集失败不影响已发布排名，统一调度器安排 5 分钟重试。已生成的结构记录幂等返回；历史回放只写 replay 来源，不修改正式榜单。

统一调度执行器需要按原有方式保持运行：

```bash
uv run python manage.py run_scheduler
```
